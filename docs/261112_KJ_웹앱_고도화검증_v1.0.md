## 결론과 적용 범위

기존 실제 동작 앱에 하루 일정 계획, 브라우저 저장·복원, 공식 정보 확인, 취향 카드 내보내기를 추가했다. 이전 사이트 검토의 핵심인 ‘출발·만남·귀가까지 이어지는 이용 흐름’을 반영했다. 기존 6문항 추천, 서버 인증, 그룹 채팅, 콘텐츠 승인 체계는 유지했다. 코드 검증은 통과했으나 공개 배포와 실제 코스 운영 검증은 완료하지 않았다.

- 기준 브랜치: `mvp/local-integrated-v1`
- 기준 커밋: `5ab39cf7c75136e92358a342baeff7845850f69f`
- 작업 브랜치: `feat/261112-journey-planner`

## 동작과 데이터 경계

일정은 사용자가 저장 버튼을 누를 때 현재 브라우저의 localStorage에 저장된다. 계정 동기화나 서버 전송은 구현하지 않았다. 공용 기기에서는 사용 후 초기화가 필요하고, 브라우저 데이터 삭제 시 복구할 수 없다. 앱 전체의 오프라인 사용이나 산행 내비게이션을 보장하지 않는다.

저장 일정에는 코스 ID와 버전만 보관한다. 코스 내용의 과거 사본으로 승인 상태를 되살리지 않는다. 화면 진입·포커스·연결 복구 및 주기 갱신에서 현재 API를 재확인한다. 사용자 준비 체크는 운영자 승인과 무관하며 한국 날짜가 바뀌거나 계획을 수정하면 유효한 체크로 취급하지 않는다.

검토 환경의 실제 승인 코스는 0개다. 새 일정은 계획 메모로 사용할 수 있지만 미확인 코스를 추천하지 않는다. 교통 노선·정류장·귀가 시각에 대해 검증되지 않은 숫자나 경로를 추가하지 않았다. 입력한 귀가 시각은 개인 목표이며 막차 정보가 아니다.

## 후속 실행안

1. QR 시연에 사용할 실제 코스와 출발·귀가 정보를 운영자가 검증한다. 출처, 확인일, 유효기간, 번역 승인과 권리 정보를 함께 등록한다.
2. Galaxy S22 Ultra 등 실제 기기에서 입력·공유·글꼴·터치를 검수하고 영어·번체중문을 원어민 검수한다.
3. Netlify 공개 호스팅에 맞는 Node·SQLite 서버의 배치·영속 저장·복구 방식을 확정한다. 프런트 빌드 성공만으로 운영 배포를 완료했다고 보지 않는다.
4. 공개 배포는 사용자 승인 후 별도로 진행한다. 결제·실사용자 수집·도메인 연결은 이번 작업 범위에 포함하지 않는다.

로컬 실행은 Node 24+에서 `pnpm install --frozen-lockfile` 후 `npm run dev`를 사용한다. Windows의 기존 `Start-KJ-Trail.cmd`도 유지했다. 검증은 `npm run verify` 또는 `node scripts/turnkey.mjs check`로 재현할 수 있다.
