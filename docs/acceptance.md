# 기능·운영 수용 기준

상태는 `계획`, `구현`, `자동 검증 통과`, `수동 검증 통과`, `미검증`, `운영 관찰`로 구분합니다. 이 표는 확인해야 할 기준이며 체크 표시나 실제 결과가 없다는 이유로 임의 통과 처리하지 않습니다. 실행 결과는 `reports/` 원장과 담당 검토 기록을 연결합니다.

| ID | 사용자·운영 결과 | 필요한 검수 증거 |
| --- | --- | --- |
| AC-01 | 비회원이 코스를 탐색하고 적격 0건을 이해한다 | 공개 API에서 초안/미승인/fixture가 실제 코스로 섞이지 않음. 표기와 빈 화면 확인 |
| AC-02 | 추천 질문 후 최대 3개 적격 코스 또는 0건이 나온다 | 같은 조건의 일관성, 통제·만료·확인 필요 제외, 입력 수정·뒤로가기. 6문항 중 교통·동행은 준비 안내이며 검증된 매칭 차원으로 과장하지 않음 |
| AC-03 | 회원 신원이 서버에서 확인된다 | 실제 계정 등록/로그인/로그아웃, 세션·비밀번호·유효성 검증, 역할 body 위조 거부 |
| AC-04 | 현재 참여자만 허용 이력을 읽고 쓴다 | 비회원·비참여자·탈퇴·정지의 직접 API 접근 거부, 참여 시각 이후 조회 |
| AC-05 | 메시지 저장·재시도가 신뢰 가능하다 | 저장 후 응답, 동일 client ID 중복 방지, 변경된 본문 재사용 거부, 재접속 스냅샷. 원전송 후 방 잠금 시 동일 재시도는 현재 권한 내 기존 메시지 반환, 새 전송은 거부 |
| AC-06 | 게시·댓글 입력이 실행되지 않고 조회 범위가 분명하다 | 입력 길이·악성 HTML·작성자 검증, 댓글 연속 작성 제한, 숨김·차단 제외 최근 100개 시간순 스냅샷. 과거 이력 페이지 이동 미구현 표시 |
| AC-07 | 신고와 관리자 조치가 실제 연결된다 | 메시지·게시물·댓글 각각 접수→권한 있는 검토→숨김/복구/기각→회원 조회 반영→감사 기록 |
| AC-08 | 관리 권한은 화면 밖에서도 제한된다 | member/content/moderator/admin 직접 API 권한 경계, 자기 권한 상승 거부 |
| AC-09 | 운영 변경과 이력을 보존한다 | 버전 충돌 409, 성공 작업·감사 기록 원자성, 감사·코스 버전 UPDATE/DELETE 거부, v2 이관의 기존 신고 보존. 실패를 성공으로 표시하지 않음 |
| AC-10 | 세 언어에서 핵심 과업이 이해 가능하다 | UI 키 검사·실문구 검수, 코스의 en/zh-TW 필수 본문과 원문/번역 승인 지문 일치, 변경 후 초안·재승인. 단일 플래그만으로 통과 불가. 로컬 같은 운영자 승인과 독립 사람 언어 검수를 분리 |
| AC-11 | 작은 화면과 보조 입력으로 조작 가능하다 | 모바일 레이아웃, 텍스트 확대, 키보드·포커스·레이블·대비 확인 |
| AC-12 | 실패·오프라인 상태를 정직하게 알린다 | 서버 실패를 빈 정상 데이터로 바꾸지 않음. 전송 실패·재시도·접속 안내 확인 |
| AC-13 | 코스 정보에 근거와 책임 범위가 있다 | 출처·기준/조회/검토 시각·적용 범위, 시각 순서·미래 시각 거부, 공개 운영자 ID 비노출. 개방 유효기한 기본 24시간 기술 상한과 운영 근거를 구분하며 안전 보장으로 표시하지 않음 |
| AC-14 | 미디어를 적법한 범위와 올바른 의미로 사용한다 | 원본·사용 권한·승인·버전·대체텍스트 확인. 생성물의 현장 증거 사용 없음 |
| AC-15 | 장애 후 복구할 수 있다 | 실제 백업·복원·재시작·이전 코드와 DB 호환성 시험, 결과 기록 |
| AC-16 | 공개 운영의 책임과 비용이 명확하다 | 실제 담당·대응 시간·호스팅·예산·보관/삭제 정책·연락 경로 확정 |
| AC-17 | MVP2가 실제 문제에 근거한다 | 배포/콘텐츠 버전·기간·분모·관찰 한계가 있는 P11 자료와 판단 기록 |

## 공개 출시 전 미검증 항목

현재 저장소는 로컬 평가 환경입니다. 승인된 실제 코스, 번역의 사람 검수, Figma 파일 대응, 자산 권리, 실제 운영 담당과 대응 시간, 호스팅, 예산, 개인정보 보관·삭제 정책, 운영 복구 증거는 빌드로 완료되지 않습니다. 각 항목은 확인된 증거를 추가한 뒤 상태를 바꿉니다.

가상의 시험 계정·fixture·개발자가 작성한 피드백은 API 동작 시험에만 사용합니다. 실제 고객 수·만족도·전환·신고 처리 성과로 집계하지 않습니다.
