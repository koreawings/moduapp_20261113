## 검증 방법과 범위

실행기를 임시 프로젝트에 복사했습니다. Node/SQLite 확인과 Node 테스트 러너는 실제 프로세스로 실행했습니다. TypeScript·Vite 위치에는 성공·실패·소스 변경을 통제하는 **시험용 대체 스크립트**를 넣었습니다. 이는 실행기 분기를 검증하기 위한 장치이며 실제 컴파일·프론트 빌드를 했다는 의미가 아닙니다.

| 호출 순서 | 조건과 명령 | 예상한 결과·관찰 |
| --- | --- | --- |
| 1 | `--help` | 종료 0, 원장 디렉터리를 만들지 않음 |
| 2 | 잘못된 인수 | 종료 2 |
| 3 | 처음 `--next` | 런타임만 PASS, 나머지 미실행, 전체 완료는 false |
| 4 | 타입 단계의 의도한 실패 후 `--resume` | 자식 종료 7을 FAIL로 기록, 실행기 종료 1, 뒤 단계 미실행, 오류 로그 존재 |
| 5 | 같은 입력에서 실패 조건만 해제 후 `--resume` | 같은 실행 ID로 재개, 타입 시도 이력 2개 보존, 자동 검사 완료. P11/P12는 계속 BLOCKED_NO_EVIDENCE |
| 6~7 | `pnpm-workspace.yaml` 변경 후 `status`, `--resume` | 이전 입력 변경 표시, 새 실행 ID로 처음부터 검증 |
| 8 | 설치된 React manifest 변경 후 `--resume` | 새 입력·새 실행 ID |
| 9 | PS1·CMD 실행 보조 파일 추가 후 `--resume` | 새 실행 ID, CMD가 입력 목록에 포함됨 |
| 10 | `public` 파일 추가 후 `--next` | 새 실행 ID, 런타임 다음 단계는 미실행 |
| 11 | 타입 단계 실행 중 소스 변경 | 해당 원장 stale, 실행기 종료 1, 이후 단계 미실행 |

| 17 | 손상된 JSON 원장에서 `--resume` | 종료 1, 손상 원본을 덮어쓰지 않음 |

## 반영한 수정과 남은 한계

- 입력 지문에 pnpm 작업공간·실행 보조 파일·공개 정적 파일·주요 설치 메타데이터를 포함했습니다.
- 로그를 단계 완료 때만 쓰지 않고 출력이 도착할 때 바로 추가합니다. 종료 결과를 남기지 못한 시도는 재개 시 통과시키지 않습니다.
- 죽은 PID의 잠금을 자동 제거하는 과정의 동시 재개 경쟁을 피하도록 알려진 잠금의 수동 복구 절차를 문서화했습니다.
- 전체 의존성 파일의 무결성, 두 OS 프로세스의 실제 동시 경쟁, 5분 타임아웃, 실제 SIGINT/강제 종료, 디스크 부족·권한 오류·정전 복구는 이 17회 기록의 검증 범위가 아닙니다.
- 이 결과로 실제 콘텐츠 승인, 번역 품질, 독립된 사람 검토, 운영 복구, 공개 호스팅, 고객 만족·구매가 검증되지는 않습니다.

이후 실행기 코드가 달라지면 위 해시를 최신 코드의 검증 근거로 재사용하지 않습니다. 원본 기록은 보존하고 변경 범위에 맞게 새 검증을 남깁니다.
