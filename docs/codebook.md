# 코드북 — 실제 로컬 구현 지도

이 문서는 계획상의 미래 폴더가 아니라 현재 코드의 책임을 설명합니다. 검증 통과 여부는 실행 시점의 원장과 로그를 확인합니다. 실제 코드 경로·계약이 달라지면 함께 갱신합니다.

## 인증·데이터 경계

브라우저는 같은 출처의 `/api`를 호출합니다. 세션은 HttpOnly 쿠키이며 서버는 매 요청에서 세션과 DB의 현재 역할·정지 상태를 확인합니다. 회원가입은 일반 회원만 생성합니다. 관리자 부여는 등록된 계정에 대한 로컬 CLI 경로로 제한합니다. 프론트에서 메뉴를 숨기는 것만으로 권한을 보장하지 않습니다.

`server/app-database.mjs`가 저장소를 선택합니다. `DATABASE_URL`이 있으면 `server/postgres-database.mjs`의 PostgreSQL 풀을 사용하고, 없으면 `server/database.mjs`의 SQLite를 사용합니다. `db/schema.sql`은 PostgreSQL 스키마와 전용 역할의 최소 권한을 정의합니다. 자동 API 시험은 별도의 임시 DB를 사용합니다. `server/fixtures.mjs`의 예시는 명시적인 demo 조회로만 제공하며 운영 코스 테이블과 분리합니다.

스키마 v2는 기존 신고를 보존하며 댓글 신고를 지원하도록 이관합니다. `audit`와 `course_versions`에는 UPDATE·DELETE를 거부하는 SQLite 트리거를 적용합니다. 앱과 일반 SQL 변경으로 이력을 덮어쓰는 것을 막는 장치이며, DB 파일·스키마를 직접 제어하는 OS 소유자까지 막는 변조 방지 보장은 아닙니다. 백업·복원과 이관 검증은 별도 증거가 필요합니다.

## 채팅의 현재 계약

- 전송 완료는 서버 저장 응답 후 표시합니다.
- 작성자와 `clientMessageId` 조합의 중복 저장을 막습니다. 같은 키로 다른 본문·방을 보내면 충돌입니다.
- 동일한 내용의 재시도는 현재 권한과 메시지의 조회 가능 상태를 확인한 뒤 기존 저장 메시지를 반환합니다. 원전송 이후 방이 잠겨도 이 조회형 재시도는 가능하지만 새 메시지는 거부합니다.
- 이력은 현재 방 참여 이후의 최근 최대 200개입니다. 다시 참여하면 새로운 참여 범위가 적용됩니다.
- 갱신은 3초 폴링입니다. 스냅샷을 대체하여 숨김·차단 결과를 반영합니다.
- 사용자 차단은 자신의 조회에서 상대의 게시·메시지를 숨기는 동작입니다. 동일 방에서 상대가 나의 글을 못 보는 완전한 상호 차단을 약속하지 않습니다.
- 전송/참여 잠금과 읽기 금지는 같은 개념이 아닙니다. 방 잠금의 구체 효과는 API 계약을 따릅니다.
- 이미 상대 기기에 전달된 메시지를 완전히 회수한다고 보장하지 않습니다.

게시물·메시지·댓글 모두 신고 대상입니다. 댓글도 권한 있는 운영자가 숨김·복구·기각을 처리하며 감사 기록을 남깁니다. 공개 댓글은 숨김·차단을 제외한 최근 최대 100개를 그 범위 안에서 시간순으로 반환합니다. 과거 댓글 페이지 이동은 아직 없으며, 댓글 작성 제한은 게시물별이 아니라 사용자별 분당 30회입니다.

## 콘텐츠·운영 상태

초안·공개·게시중단과 추천 자격을 구분합니다. 승인된 정적 설명이라도 현재 상태가 불명확하거나 유효기한이 지난 경우 능동 추천에서 제외합니다. 출처 URL과 날짜가 있다는 것만으로 실제 사실 검증이 자동 완료되는 것은 아닙니다. 실제 검토자의 자료 확인이 필요합니다.

현재 코스는 원문의 `title`·`summary`·`startPoint`와 영어(`en`)·번체중문(`zh-TW`)의 동일 항목을 저장합니다. 서버가 원문 및 번역 내용의 지문을 계산하므로 `translationStatus:'approved'` 플래그만 보내서는 승인되지 않습니다. 필수 두 언어 내용과 승인 당시 원문·번역 지문이 일치해야 합니다. 원문 또는 번역을 바꾸면 초안·재검토 상태가 되며, 변경 저장과 승인을 하나의 요청으로 합치지 않습니다.

로컬 모드는 동일 운영자의 저장 후 별도 승인을 허용하고 이를 기록합니다. `GET /admin/courses`의 `policy`는 `approvalMode:'local-single-operator'`, `separateApproverRequired:false`와 필수 언어·상태 유효기한 상한을 알려줍니다. 별도 사람의 독립 번역 검수가 완료되었다는 뜻은 아닙니다. 공개 응답은 운영자 로그인 ID 대신 `reviewed`·검토 시각을 사용하며 `reviewer`는 null입니다.

현재 개방 상태의 기본 유효기한 상한은 승인 시각부터 24시간입니다. 서버 생성 옵션은 최대 7일까지만 허용합니다. 이는 로컬 구현의 기술 상한이며 공식 현장 상태 보장이나 모든 정보에 적용하는 운영 신선도 기준이 아닙니다. 운영 근거에 맞는 더 짧은 기한이 필요할 수 있습니다. 기한이 지난 개방 상태는 공개 응답에서 `unknown`으로 바뀌고 마지막 확인 정보는 남습니다. 통제 상태는 재검토 전까지 유지하며 불확실한 상태는 추천에서 제외합니다.

검토 시각은 수집 시각보다 이르지 않아야 하고 현재 상태 자료의 수집·출처 기준 시각은 미래일 수 없습니다. 미래 시행 예정 공지는 별도 모델이 필요합니다. 6문항 중 교통수단·동행은 준비 안내로 사용하며 검증된 코스 매칭 차원이라고 표시하지 않습니다. 최신 상세 계약은 [API v1의 Claude 검토 반영 사항](../API-CONTRACT.md)을 따릅니다.

## 명령과 실제 결과의 연결

```powershell
npm run verify
npm run turnkey -- check
```

`verify`는 `reports/verification.json`과 단계 로그를 작성합니다. `turnkey`는 별도의 `reports/turnkey/ledger.json`에 입력 지문과 단계별 실행 이력을 작성합니다. 한 도구의 결과를 다른 도구의 실행 기록으로 복제하지 않습니다. 보고서에서 명령·커밋·Node 버전·원본 증거를 연결합니다.

## 갱신 규칙

API 변경은 계약·프론트 타입·테스트·운영 안내를 함께 갱신합니다. 실행 프롬프트 변경은 프롬프트 ID·버전·실제 모델·입력·결과를 남깁니다. 원문 프롬프트의 후속 요구를 현재 기능으로 둔갑시키지 않습니다. 앱 사용자용 AI 기능을 추가하면 개발 프롬프트와 별도 계약·평가를 만듭니다.
