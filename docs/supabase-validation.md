# Supabase 연결 검증 — 2026-11-13

`DATABASE_URL`로 PostgreSQL을 선택하고 기존 Node API의 회원·세션·콘텐츠·커뮤니티 저장을 연결했다. 브라우저 API 계약과 권한 검사는 유지한다. 서버와 관리자 CLI 모두 같은 환경변수와 DB 어댑터를 사용한다.

## 실행 결과

- `npm run verify`: TypeScript, 기존 기능 및 연결 설정 테스트 37개, PostgreSQL 통합 테스트 7개, Vite 빌드 통과.
- 격리 PostgreSQL 시험: 실제 `pg` 드라이버로 회원/세션, 참여 이후 메시지 조회, 중복 전송, 버전 충돌, 신고/숨김, 감사 실패 롤백, 코스 이력, 중첩 savepoint, 읽기 전용 트랜잭션을 확인했다. 테스트의 PGlite 연결은 운영 DB를 사용하지 않는다.
- 실제 Supabase: `kj_trail_backend` 계정으로 접속하고 클라이언트 소켓의 TLS 암호화 및 인증서 검증 성공을 확인했다.
- 임시 회원·게시글·댓글·채팅을 API로 저장한 뒤 앱과 DB 풀을 종료했다. 새 앱/풀에서 로그인, 세션 및 저장 자료를 다시 읽었다. 메시지 재시도는 한 건으로 유지됐다.
- 실제 서로 다른 DB 풀의 쓰기 요청이 같은 트랜잭션 advisory lock을 기다린 후 진행됨을 확인했다. 이 검사에는 데이터 변경이 없었다.
- 검증에서 생성한 임시 회원·세션·참여·게시글·댓글·메시지만 정리하고 잔여 0건을 확인했다. 기존 자료는 삭제하지 않았다.
- 마지막 `/api/health` 응답은 `storage: "postgresql"`, `ok: true`였다. 공개 코스는 기존처럼 0건이다.

## 연결과 운영 범위

실제 `.env.local`은 Git과 배포 ZIP에 포함하지 않는다. 서버용 DB 역할과 공식 공개 CA 인증서를 사용한다. 원격 연결의 인증서 검증을 해제하지 않는다. 연결 실패 시 SQLite로 자동 대체하지 않는다.

요청별 트랜잭션은 권한 확인, 버전 검사, 저장, 감사 기록을 함께 묶고 커밋 후 성공 응답/쿠키를 보낸다. 앱 서버 및 관리자 CLI의 쓰기는 직렬화하고 읽기는 공유 잠금을 사용한다. 이는 기존 SQLite의 일관성 모델을 유지하기 위한 선택이며 대규모 처리량 검증은 포함하지 않는다.

서버는 기본적으로 루프백 주소에서 실행한다. 이 검증은 공개 HTTPS 호스팅, 운영 백업 복구, 실제 코스 승인 또는 실사용자 성과 검증을 대신하지 않는다. 개인 여행 계획과 저장 목록은 기존처럼 브라우저 저장소를 사용한다.
