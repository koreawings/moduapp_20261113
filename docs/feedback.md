# 실제 피드백 → 수정 → MVP2

P11/P12는 프롬프트가 준비되어 있어도 실제 근거 없이 완료할 수 없습니다. 로컬 시험 성공은 실제 여행자의 행동이나 공개 서비스 운영 경험이 아닙니다. 현재 고객·매출·만족도·운영 성과는 이 문서에서 주장하지 않습니다.

## P11을 시작할 입력

1. 관찰 대상인 실제 배포/콘텐츠 버전과 기간.
2. 관찰 방식, 이벤트 정의, 대상 고객 과업, 수집 범위와 누락.
3. 실제 피드백·문의·오류·운영 기록과 비식별 근거.
4. 수치가 있다면 분모와 계산 방식. 수집하지 않은 값은 0이 아니라 미측정.

자료가 부족하면 `BLOCKED_NO_EVIDENCE`로 기록하고 수집 설계·이벤트 사전·사용성 질문 준비는 계속할 수 있습니다. 정량 지표만 있는 경우 사용자의 의도를 확정하지 않습니다. 소수 관찰은 그 한계를 함께 남깁니다.

## 개선 카드

| 항목 | 작성 내용 |
| --- | --- |
| 고객 과업 | 어떤 이용자가 무엇을 하려 했는가 |
| 버전·범위 | 배포/콘텐츠/프롬프트 버전, 기간·환경 |
| 기대·실제 | 기대한 결과, 실제 관찰, 재현 여부 |
| 근거·한계 | 원본 위치, 수집 방법, 분모·누락, 시험/실사용 구분 |
| 원인 가설 | 콘텐츠·현지화·디자인·개발·운영을 함께 검토 |
| 최소 개선 | 새 기능보다 작은 수정으로 해결 가능한지 |
| 검수·결과 | 수용 조건, 실제 실행 결과, 독립 확인 |
| 재관찰 | 같은 과업에서 달라진 점·변경 유지/수정/중단 |

## 최소 측정 후보

추천 적격 0건, 추천 상세 열람, 언어별 핵심 과업, 첫 게시·채팅 참여, 전송 실패·재시도, 정보 오류 제보, 미처리 신고·문의는 후보입니다. 실제 계측 구현·동의·보관 정책과 비용을 확인하기 전 측정 완료로 표시하지 않습니다. 분석 로그에 채팅 원문·정밀 위치·불필요한 개인정보를 포함하지 않습니다.

## MVP2 판단

관찰된 문제 → 증거 강도·고객 영향 → 최소 개선 가설 → 검증 방법 → 운영·비용·호환성 → 선택/보류의 순서로 기록합니다. DM, 위치 공유, 사진, AI 상담 등의 기능을 자동 확장 목록으로 확정하지 않습니다. 콘텐츠 ID, 번역 버전, API, Figma 컴포넌트, 자산·데이터 권리와 운영 기록의 연속성을 유지합니다.

보안·권한·데이터 노출의 실제 결함은 새 기능 실험과 별도로 우선 조치합니다. 사실과 다른 현행 정보를 발견하면 관련 추천·게시 상태부터 검토하고 수정 근거를 남깁니다.
