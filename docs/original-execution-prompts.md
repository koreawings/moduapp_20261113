### DEV-P03 — 코스·출처·승인 데이터

```text
코스·POI·출처 증거·공지·번역 버전의 데이터 계약과 조회·게시 흐름을 구현하라.
실제 DB와 기존 스키마를 먼저 읽고, 확인한 개발/시험 환경에서 재현 가능한 변경을 기록하라.
승인 코스 버전과 소스별 증거를 연결하고 source_effective_at/fetched_at/reviewed_at/reviewer/scope를 구분하라. 중요 사실에만 필요한 세부 출처 연결을 추가하라.
초안·검토·승인·공개·비공개와 추천 자격을 별도로 관리하라. 미승인 버전은 공개하지 않는다. 승인된 정적 설명이 공개 가능하더라도 현재 상태 미확인·통제·충돌이면 능동 출발 추천에서 제외하라.
갱신 기준은 데이터 유형별 설정으로 두고 근거 없는 기본 TTL을 만들지 마라. 원문 변경 시 번역·추천 자격을 재평가하라.
수용 기준: 출처 누락·조회 실패·오래된 정상 표시·통제·충돌·비공개 개정판 시험을 통과한다. 조회 실패를 통제 없음으로 바꾸지 않는다. 승인 자료가 없으면 명백한 가상 fixture만 사용하라.
```

## 5. 프롬프트 품질과 코드북 갱신

이 13개 지시서는 실제 작업을 위한 첫 버전이다. 아직 개발 작업에서 실행해 성공률을 측정한 것은 아니다. 실행할 때 프롬프트 버전·실제 모델 ID·코드 커밋·입력과 결과·채택/수정 이유를 남긴다. 긴 만능 프롬프트로 한 번에 전부 수행하기보다 작은 작업을 검토한다.

코드북 C01~C10에는 실행 과정에서 생긴 실제 경로·명령·계약·테스트·운영 절차를 채운다. 계획과 다른 구현이 생기면 이유와 영향을 반영하고, 원본 코드를 복제하는 대신 커밋·문서 링크를 유지한다.
