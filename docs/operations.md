# 로컬 운영·관리자·복구 절차

이 문서는 실행 절차와 확인할 기준입니다. 실제 복구 시험·담당자 배정·공개 운영 완료를 뜻하지 않습니다. 결과를 기록할 때 [수용 기준](acceptance.md)의 양식을 사용합니다.

## 관리자 업무

1. 회원 등록 후 로컬 CLI로 필요한 계정에만 관리자 역할을 부여합니다. 기본 관리자 비밀번호는 없습니다.
2. 코스는 출처·기준 시각·조회 시각·검토자·현재 상태·유효기한과 영어·번체중문 코스명/설명/출발지의 내용을 확인합니다. 실제 검토를 하지 않은 예시를 승인·게시하지 않습니다.
3. 원문·번역 변경을 먼저 초안으로 저장하고 내용을 다시 확인한 뒤 별도 승인/게시 요청을 합니다. 변경과 승인을 동시에 보내면 거부됩니다. 서버의 지문 확인은 번역의 의미가 정확하다는 검수가 아닙니다. 승인/게시·게시중단 결과를 회원용 공개 화면에서도 확인하고, 최신 상태에 문제가 생기면 추천 자격과 정적 설명의 공개 여부를 구분해 판단합니다.
4. 메시지·게시물·댓글 신고의 대상·사유·현재 숨김 상태를 확인한 뒤 숨김/복구/기각을 처리합니다. 조치 사유를 남기고 서버 성공 응답, 회원 화면 반영, 감사 기록을 확인합니다. 공개 댓글 조회는 최근 최대 100개이므로 목록에 없다는 이유만으로 삭제되었다고 판단하지 않습니다.
5. 다른 운영자의 변경으로 충돌이 나면 최신 자료를 다시 읽고 의도를 확인합니다. 이전 버전을 강제로 덮어쓰지 않습니다.
6. 회원 제재·방 잠금은 영향 범위가 다릅니다. 잠금은 전송/새 참여를 막는 운영 기능이며 현재 참여자의 기존 읽기까지 모두 금지하는 기능으로 설명하지 않습니다.

관리자 통계는 현재 로컬 DB 건수입니다. 공개 서비스 이용자 수, 활성 사용자, 만족도, 전환 또는 실사용 성과가 아닙니다. 연결되지 않은 지도·날씨·Runway·외부 서비스 상태를 정상이라고 표시하지 않습니다.

현재 승인은 **로컬 단일 운영자 모드**입니다. 같은 운영자가 저장 후 별도로 승인할 수 있으며, 독립 검토자를 강제하지 않습니다. 관리 API의 `policy`에 이 모드와 필수 번역 언어·기술 상한이 표시됩니다. 외부 공개 전 실제 검토자의 자격·담당·독립 검수 필요 여부를 운영 정책으로 정하고 그 결과를 남깁니다. 공개 화면에 운영자 로그인 ID를 노출하지 않으며 확인 여부·시각과 근거를 표시합니다.

감사와 코스 버전 이력은 DB 트리거가 UPDATE·DELETE를 거부하는 추가 기록 방식입니다. 이력 수정으로 오류를 숨기지 않고 새 조치와 사유를 남깁니다. DB 소유자가 스키마·파일을 직접 바꾸는 것까지 방지하는 장치는 아니므로 백업 보관과 접근 관리가 필요합니다.

## 자료·자산 관리

원본 Drive 자료와 승인본을 구분하고 자산 ID·버전·권리·사용 위치를 남깁니다. Figma 화면·토큰의 승인본이 무엇인지 확인합니다. Runway 생성물은 생성 사실과 사용 승인을 별도로 기록하며 현장 사진·갈림길·안전 증거를 대체하지 않습니다. 소유자의 Drive·GitHub·Runway 자격증명을 방문자에게 전달하지 않습니다.

출처의 `sourceEffectiveAt`, 수집의 `fetchedAt`, 사람 검토의 `reviewedAt`을 분리합니다. 검토 시각은 수집 시각 이후여야 하며, 현재 상태 자료에 미래 수집·출처 기준 시각을 넣지 않습니다. 미래 시행 예정 공지는 이 모델로 처리하지 않습니다. 데이터마다 적용 구간·시설·기준을 확인하고 조회 장애를 정상 또는 통제 없음으로 바꾸지 않습니다.

서버는 개방 상태의 유효기한을 기본적으로 승인 시각부터 최대 24시간으로 제한합니다. 서버 생성 옵션의 상한도 7일 이내입니다. **기술 상한은 현장 안전 보증이나 공식 갱신 주기가 아닙니다.** 이 시간을 채운다고 자동 연장하거나 모든 정보에 동일한 신선도 기준을 적용하지 않습니다. 실제 근거의 적용 종료 시각이 더 이르면 그 기한을 사용합니다. 만료된 개방은 공개 화면에서 확인 필요로 표시하고 추천에서 제외하며, 통제는 새 검토 전까지 유지합니다.

## 백업

`DATABASE_URL`이 설정된 경우 자료는 Supabase PostgreSQL에 있습니다. 아래 SQLite 파일 복사 절차는 PostgreSQL 백업을 만들지 않습니다. Supabase 프로젝트의 백업 제공 범위·보관 기간을 확인하고 별도 복원 환경에서 검증해야 합니다. 운영 역할 `kj_trail_backend`는 제한된 앱 역할이며 스키마 변경/전체 백업용 관리자 역할과 구분합니다. DB URL과 인증서 경로는 서버와 관리자 CLI에 동일하게 적용합니다. SQLite 복원 시험을 할 때에는 해당 프로세스의 `DATABASE_URL`을 빈 값으로 명시해야 `.env.local`의 원격 설정 대신 `KJ_DB_PATH`가 사용됩니다.

현재는 자동 백업·자동 만료 삭제 기능이 설정된 서비스가 아닙니다. SQLite의 WAL 모드에서는 실행 중인 DB 본체만 복사하면 최신 변경을 빠뜨릴 수 있습니다. 이 로컬 절차는 **서버와 관리자 CLI를 모두 종료한 뒤** 파일을 복사합니다.

PowerShell에서 프로젝트 폴더를 열고, 서버를 종료한 것을 확인한 뒤 실행합니다. 사용자 지정 `KJ_DB_PATH`를 사용했다면 실제 경로를 확인한 후 해당 경로를 사용합니다.

```powershell
$kjDbFile = Join-Path (Get-Location) 'data\kj-trail.sqlite'
if (-not (Test-Path -LiteralPath $kjDbFile)) { throw '기본 DB가 없습니다. 실제 DB 경로를 확인하세요.' }
$kjBackupDir = Join-Path (Get-Location) ('reports\backups\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $kjBackupDir -ErrorAction Stop | Out-Null
foreach ($kjSuffix in @('', '-wal', '-shm')) {
  $kjSourceFile = $kjDbFile + $kjSuffix
  if (Test-Path -LiteralPath $kjSourceFile) {
    Copy-Item -LiteralPath $kjSourceFile -Destination $kjBackupDir -ErrorAction Stop
  }
}
Get-ChildItem -LiteralPath $kjBackupDir | Select-Object Name, Length
```

백업에는 회원 정보와 메시지가 포함될 수 있습니다. Git·공개 문서·공유 드라이브에 무심코 업로드하지 않습니다. 복사한 시각, 코드·스키마 버전, 파일 해시와 복구 시험 결과를 별도 기록합니다. 백업 파일 목록 확인만으로 복구 통과 처리하지 않습니다.

## 복원 시험과 되돌리기

1. 원본 DB와 현재 코드 버전을 보존합니다. 실행 중인 서버나 원본 DB에 덮어쓰기하지 않습니다.
2. 백업 파일들을 별도의 `reports/recovery/<시험시각>/` 폴더에 복사합니다. 본체·WAL·SHM의 기본 파일 이름을 일치시킵니다.
3. 새 터미널에서 `KJ_DB_PATH`를 복원 사본의 절대 경로, `PORT`를 8788 등 사용하지 않는 포트로 설정한 뒤 `npm start`를 실행합니다.
4. 별도 브라우저 프로필/시크릿 창으로 건강 상태, 실제 시험용 로그인, 콘텐츠·게시·채팅·감사 기록을 확인합니다. 쿠키는 포트별로 분리되지 않으므로 기존 운영 창과 혼용하지 않습니다.
5. 시험 서버를 종료하고 결과를 기록합니다. 재사용할 터미널의 환경변수를 기존 값으로 돌립니다. 원본 서비스는 원래 DB와 포트로 시작합니다.

코드를 이전 버전으로 돌리는 것만으로 DB 변경이 자동 복구되지 않습니다. 이전 코드와 현재 스키마의 호환성을 먼저 확인합니다. 현재 스키마보다 새로운 버전의 DB를 읽으려 하면 서버가 거부할 수 있습니다. 데이터 삭제·초기화를 복구 방법으로 사용하지 않습니다.

현재 스키마 v2는 기존 신고 보존과 댓글 신고 지원, 감사·코스 버전 이력의 추가 기록 트리거를 포함합니다. v1 백업에서 시험 복원할 때는 이관 후 기존 신고 건수·내용과 트리거의 수정/삭제 거부를 확인하고, 원본 v1 백업은 그대로 보관합니다. 이 문서가 실제 이관·복구 시험 통과 기록을 대신하지 않습니다.

## 장애 대응

| 현상 | 먼저 확인할 사항 | 기록할 근거 |
| --- | --- | --- |
| 로그인·API 오류 | 서버 실행, DB 경로, 세션, 제재·권한, 실제 응답 코드 | 발생 시각·버전·재현 요청·민감정보 없는 오류 |
| 메시지 미전송 | 네트워크, 방 참여·잠금, 서버 저장 결과, 동일 전송 ID | 전송 상태·재시도 결과·중복 여부 |
| 코스 정보 충돌 | 공식 원문·적용 범위·기준 시각·추천 자격 | 원문 링크·검토 내용·게시/추천 변경 이력 |
| 관리자 저장 충돌 | 최신 버전, 앞선 조치, 현재 권한 | 409/403 등 응답과 최종 처리 |
| 검증 실패 | 첫 실패 단계, 입력 지문, 로그 | `reports/` 원본, 수정 후 새 실행 결과 |

## 공개 운영 전에 결정할 사항

콘텐츠 승인·현지화·커뮤니티 담당 역할과 실제 대응 시간, 개인·신고·채팅 데이터의 보관·삭제 기준, 호스팅·TLS·모니터링, 비용 한도·알림 책임, 백업 주기·복구 목표, 외부 자료 공급자·이용 조건이 필요합니다. 특정 인원수·기한·법적 의무를 이 문서가 임의로 확정하지 않습니다.

관찰된 실제 고객 의견은 [피드백 절차](feedback.md)로 넘깁니다. 운영상의 가정과 설정값을 실제 성과나 사용자 요구로 보고하지 않습니다.
