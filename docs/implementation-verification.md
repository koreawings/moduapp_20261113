# 로컬 MVP 구현·검증 기록

검수일: 2026-11-02 (KST). 이 문서는 실제 구현·실행 결과이며 공개 출시 기록은 아닙니다.

## 자동 검증

`node scripts/turnkey.mjs check`에서 Node24/SQLite, 의존성, TypeScript, 실제 HTTP·SQLite/추천 도메인 테스트 **26/26**, Vite 프로덕션 빌드가 통과했습니다. 개발 DB가 아닌 격리된 임시 DB를 시험했습니다. 최종 입력 지문과 단계별 원본 로그는 `reports/turnkey/ledger.json`을 확인합니다.

첫 통합시험에서는 동시 빈 DB 초기화의 WAL 잠금 경합으로 25/26이 통과했습니다. 초기 모드 확인·제한된 BUSY 재시도·실패 연결 정리를 적용하고, 해당 시험을 유지한 채 단독 3회 및 전체 시험을 다시 통과했습니다. 실패 로그는 삭제하지 않았습니다. 실행기 자체는 [별도의 17회 CLI 검증](turnkey-review.md)을 수행했으며 그 수치를 앱 기능 시험 수로 합치지 않습니다.

첫 GitHub의 새 Ubuntu 환경에서는 pnpm11이 이전 onlyBuiltDependencies 설정을 무시하여 esbuild 설치 승인을 인식하지 못했습니다. [pnpm11 공식 빌드 설정](https://github.com/pnpm/pnpm/blob/main/pnpm11/docs/settings/build.md)에 맞춰 `allowBuilds: {esbuild: true}`로 수정했습니다. 전체 빌드 스크립트 허용이나 검증 생략은 하지 않았습니다. 로컬 frozen-lockfile 설치도 종료코드0으로 확인했고, 새 커밋의 CI 결과는 PR에서 확인합니다.

## 실제 브라우저에서 확인한 범위

- 개발 서버와 프로덕션 빌드의 홈·코스 탐색, 실제 승인 코스 0건 안내.
- 별도 가상 샘플 3건, 상세·출처 없음 표시·브라우저 저장 확인.
- 6개 질문→3가지 출발 전 확인→승인 코스 없음 결과. 교통·동행은 준비 메모라는 설명.
- 운영 DB와 분리한 `work/browser-qa.sqlite`의 합성 계정으로 로그인. 기본 계정을 제품에 넣지 않음.
- 첫 계정은 브라우저에서 방 참여·메시지 전송, 두 번째 합성 계정은 HTTP로 참여·응답. 브라우저에서 두 메시지 조회 및 서버 재시작 후 보존 확인.
- 브라우저 신고→관리자 실제 신고목록→사유를 적어 숨김→채팅 재진입 시 해당 메시지 제거→감사 기록 확인.
- 390×844 viewport의 모바일 화면과 한/영/번체중문 전환. 한국어·영어 DOM의 가로 넘침 없음(clientWidth=scrollWidth=375). viewport 시험 후 기본 크기로 복원.
- Windows `Start-KJ-Trail.cmd`로 프로덕션 서버 실행 확인. 서버는 127.0.0.1에만 바인딩.

캡처: `reports/screenshots/desktop-home.jpg`, `mobile-home.jpg`, `admin-audit.jpg`. 캡처와 실제 QA DB는 Git 소스에 포함하지 않습니다. 브라우저 자동화를 실제 고객 사용성 조사나 실제 스마트폰 네트워크 시험으로 부르지 않습니다.

## 구현·운영 경계

실제 구현: React/TS 화면, Node HTTP API, SQLite 영속 저장, 회원/세션, 코스와 번역 승인·버전, 추천, 저장, 게시판/댓글, 3초 폴링 그룹채팅, 신고/차단/관리자/감사/피드백.

미완료 운영 조건: 검증된 현장 코스·인간 번역검수, 호스팅/HTTPS/프록시 정책, 백업복구 훈련, 데이터 보존/삭제/개인정보정책, 운영자 배정, 외부 로그인, 실제 고객 조사, 실결제/수령/환불. Figma 저장 파일과 Runway 생성 자산은 만들지 않았습니다. 자체 SVG는 실제 지형도가 아닙니다.

로컬 채팅은 현재 참여 이후 최근200개, 댓글은 최신100개입니다. WebSocket·무제한 이력·푸시·1:1DM·사진 업로드·오프라인 내비·구조·상시 AI는 없습니다. 저장은 정적 설명의 브라우저 스냅샷입니다.

## 다음 실행

`Start-KJ-Trail.cmd` → 브라우저 `http://127.0.0.1:8787` → 자신의 로컬 계정 등록 → 필요한 경우 명시적 CLI 관리자 부여. 코드 변경 후 `node scripts/turnkey.mjs check` 또는 `--resume`으로 재검증하고 빌드를 갱신합니다. 원래 13개 프롬프트와 실제 의존 순서는 [턴키 문서](turnkey.md), 코드 구조는 [코드북](codebook.md), 고객 관측→수정은 [피드백 절차](feedback.md)를 따릅니다. P11/P12는 실제 근거 없이 통과시키지 않습니다.
