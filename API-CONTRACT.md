# API v1

All endpoints under `/api`, JSON; errors `{error: string, code: string}` with non-2xx. GET /health returns `{ok, mode:'local'|'hosted', contentMode:'unverified', storage:'sqlite'|'postgresql'}`. Client fetch uses same-origin cookie. POST/PATCH/DELETE JSON, Origin validated when present. Dates ISO UTC. Entity versions integers. IDs opaque strings. User `{id,username,displayName,role:'member'|'content'|'moderator'|'admin',suspended:boolean}`.

Auth: GET /session -> `{user: User|null}`; POST /auth/register `{username,displayName,password}` and POST /auth/login `{username,password}` -> `{user}` + HttpOnly cookie. POST /auth/logout -> `{ok:true}`. Register only member. Password >=12 chars. Local CLI grants admin to registered account.

Courses: GET /courses -> `{courses:Course[]}` approved published only, plus explicitly separate demo fixtures if `?demo=1` returning `{courses,fixture:true}`. Course `{id,title,summary,durationMinutes,difficulty:'easy'|'moderate'|'hard',themes:string[],startPoint,sourceUrl,sourceEffectiveAt:null|string,fetchedAt:null|string,reviewedAt:null|string,reviewer:null|string,status:'draft'|'published'|'withdrawn',condition:'unknown'|'open'|'closed',conditionValidUntil:null|string,translationStatus:'pending'|'approved',isFixture:boolean,version:number}`. Only status=published, not fixture, condition=open with future validity, reviewed data and approved translation eligible for active recommendation. No verified courses => genuine empty state. Fixture preview never departure recommendation. GET /courses/:id. GET /courses?demo=1 can be available in local review, all records labelled fictional.

Community: GET /rooms -> `{rooms:[{id,name,description,locked:boolean,joined:boolean}]}`; POST /rooms/:id/join -> `{ok:true}`; DELETE /rooms/:id/membership -> `{ok:true}`; GET /rooms/:id/messages -> `{messages:Message[]}` full authorized bounded snapshot of current membership since joined_at, hidden/blocked excluded. Poll every 3s; full replacement removes hidden content. Message `{id,roomId,authorId,authorName,body,createdAt,clientMessageId}`. POST /rooms/:id/messages `{body,clientMessageId}` -> `{message}` (durable, unique by author+client ID; conflict with altered payload); auth/suspension/current membership checked on every request. POST /blocks `{userId}`; DELETE /blocks/:userId. POST /reports `{targetType:'message'|'post',targetId,reason}` -> `{report}`.

Board: GET /posts -> `{posts:[{id,title,body,authorId,authorName,createdAt,version,comments:Comment[]}]}` public published unhidden posts; POST /posts `{title,body}` -> `{post}`; POST /posts/:id/comments `{body}` -> `{comment}`. Comments `{id,authorId,authorName,body,createdAt}`. GET /feedback not public; POST /feedback `{category,body}` authenticated -> `{ok:true}`.

Admin: GET /admin/overview -> `{counts:{users,courses,reports,openReports,messages},contentMode,capabilities:string[]}`; GET /admin/courses -> `{courses}`; POST /admin/courses full editable Course fields except id/version/reviewer + `{reason}`; PATCH /admin/courses/:id mutable fields + `{version,reason}` -> `{course}`. Only content/admin; records need actual sources to publish, approval stamps reviewer server-side. GET /admin/reports -> `{reports:[{id,targetType,targetId,reason,status,version,createdAt}]}`; POST /admin/reports/:id/resolve `{action:'hide'|'restore'|'dismiss',reason,version}` -> `{ok:true}` (moderator/admin). GET /admin/users -> `{users}`; PATCH /admin/users/:id `{suspended,reason}` moderator/admin (may not suspend self/admin); POST /admin/rooms/:id/lock `{locked,reason}` moderator/admin. GET /admin/audit -> `{entries:[{id,actorId,action,targetId,reason,createdAt}]}` admin. GET /admin/feedback -> `{feedback}` admin. No UI role assignment endpoint. Forbidden ->403, stale version->409. Audit and successful action atomic.

Amendments agreed during implementation: User and Room have integer version. Admin user suspension and room lock require version and reject stale writes with 409. GET /blocks returns current user's block list. Admin report reads may include targetPreview, authorName and targetHidden only for moderation capability. Course PATCH accepts approve:true only as a separate approval after saving changed facts; facts change plus approve in the same PATCH returns 409. Changed source text resets publication and translation approval; server stamps reviewer/reviewedAt. Local chat is a full authorized snapshot of the latest 200 messages, not unbounded history or cursor backfill. Expired last-known open status must be displayed as unknown. Six survey questions are collected but transit/company are preparation notes, not validated course matching dimensions.

Backend owner may refine for correctness; notify frontend owner immediately. Client should show error text generically, never optimistic admin success. No static test account credentials in app. Local bootstrap: register own account then `npm run grant-admin -- username`. Test helpers may create isolated temp DB fixtures.

## Adopted Claude review amendments (2026-11-02)

These replace conflicting earlier shorthand. API remains v1 with additive fields and stronger validation; SQLite migration v2 preserves existing reports and applies append-only triggers to audit/course_versions.

- Course adds `translations:{en:{title,summary,startPoint},'zh-TW':{title,summary,startPoint}}`, `sourceFingerprint`, `translationSourceFingerprint`, `translationContentFingerprint`, `reviewed:boolean`, `recommendationEligible:boolean`, and `lastKnownCondition` on public output. Server computes fingerprints; caller-provided approval flags alone cannot establish translation approval. Required text in both locales must exist and approved fingerprints must match source and translation content. Source or translation edits invalidate publication/approval. Save changed material as draft, then separately approve. Local single-operator approval is allowed and recorded, not claimed to be independent human translation review.
- Public `reviewer` is null; authenticated content administration includes the operator identifier. Public review confirmation uses `reviewed`, not the login ID. Reviewed timestamp must be at least fetched timestamp; fetched/source effective dates cannot be future dates for a current-state record. Future scheduled notices need a separate model.
- Public expired open condition becomes `unknown`, retaining last-known metadata. Closed remains closed until reviewed. Recommendation always fails closed when source/translation/current-state evidence is missing, invalid or expired.
- Default maximum current-condition validity is 24 hours from approval (configurable within seven days in server construction). This is a local technical cap, not a guarantee of trail status. Admin courses response includes `policy:{maxConditionValidityMs,requiredTranslationLocales,separateApproverRequired:false,approvalMode:'local-single-operator'}`. Operational policy and a human reviewer must be established before public use.
- Reports accept `message|post|comment`. Moderation supports hide/restore/dismiss for comments as well. Public post comments are the latest 100 visible, unblocked records, returned in chronological order within that window; no older-history pagination yet. A per-user comment burst limit of 30 per minute applies; no per-post lifetime cap is implemented.
- Repeated chat clientMessageId with identical content returns the existing authorized visible message even if a room was locked after the original send. Current session/membership authorization still applies. Changed payload with the same key conflicts; new messages in a locked room are rejected.
- Login attempt limits use IP+username rather than a globally shared username key. Hosting behind proxies still needs an explicit trusted-proxy policy; this local server binds to 127.0.0.1.

End-to-end customer measurements, payment, hosted delivery and independent real-language review are not implied by these API controls.

## PostgreSQL persistence

DATABASE_URL selects PostgreSQL; an unavailable database fails startup rather than silently changing storage. Response shapes and custom session authentication stay the same. Each API request uses one connection and transaction; mutations, version checks and audit records commit together before a success response or session cookie is sent. Database operations are asynchronous. The private kj_trail schema is installed separately from db/schema.sql. Runtime kj_trail_backend permissions do not allow schema creation. PostgreSQL BIGINT values are checked before conversion to safe JSON numbers. SQLite remains available locally when DATABASE_URL is empty.

## Vercel hosted entrypoint

`api/index.js` awaits the shared request handler without listening on a socket. Hosted mode requires PostgreSQL; missing configuration or initial connection failure returns JSON 503 and never creates SQLite storage. Health and admin overview report `mode:'hosted'`. Exact deployment hosts are allowlisted, present mutation Origin must match the request's HTTPS origin, and session cookies add Secure. Only Vercel's platform-provided `x-vercel-forwarded-for` supplies the rate-limit client IP; limits remain per instance. Request bodies stay bounded to 32 KiB. See [deployment configuration](docs/vercel.md).
